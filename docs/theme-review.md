# 日記・タイムラインテーマの調査・変更レポート

## 調査

基点: main `2c3967fbae178882a9fc31064533b7af4009a0de`。既存コードは7ファイルの静的PWAで、テスト・ビルド・CIの設定はありませんでした。

確認・修正した不具合:

1. 服薬日時「不明」を保存すると、トップレベルの`time`に現在時刻が代入される。今後の保存を空文字にし、既存レコードの`certainty: unknown`も表示・並べ替え・集計時に日時未指定として扱います。既存データ自体は書き換えません。
2. 過去7日の集計に未来の記録が混入する。現在時刻以下に限定します。
3. 保存・削除失敗時に操作結果が分からない。ダイアログ内の`role=alert`で伝え、保存失敗時は入力を保持します。
4. Service Workerが同一オリジンの他アプリのキャッシュを削除する。`life-log-v数字`の旧キャッシュのみ削除し、処理対象URLも本体資産に限定します。旧クライアントを強制更新せず、同じバージョンのシェルを使います。
5. 日付だけの予定でも新規入力時に現在日時が自動設定される。予定の時刻は初期値を空欄にします。
6. 編集時に未知の追加プロパティが消える。既存レコードとdataの未編集プロパティを保持します。

## UIとデータ保護

日記入力、日付見出し、本文を読めるカード、落ち着いた緑と紙色を使った独自のテーマを追加しました。テーマは設定から変更し、従来テーマを初期値として維持します。全記録機能・JSON v1互換性を維持し、DBのバージョン・ストア・キー・種別は変更しません。

ユーザーの実データは取得せず、検証には架空データだけを使いました。通信API・外部画像・フォント・解析ツールは追加していません。CSPの`connect-src 'none'`でも通信を制限します。JSONバックアップは引き続き端末へのダウンロードで、暗号化はされません。

## 検証

`npm run check`および`npm test`で以下を検証します。

- 両テーマで全8種別の追加・編集画面・削除、フィルタ
- IndexedDB v1の既存レコードがテーマ切替・再読込・他の記録の操作で変わらないこと
- 編集時のID・createdAt・追加プロパティ保持
- JSON v1のエクスポートと復元、破損JSONを拒否して既存データを保持
- 服薬日時不明、日付だけの予定、未来記録の集計除外
- 書込失敗時のエラー表示と入力保持
- 320/390/768px幅の横スクロール、選択状態、見出しへのフォーカス
- 両テーマの5画面と入力ダイアログにaxe-core（WCAG 2 A/AA、2.1 AA）を実行
- アプリ操作中の外部リクエストがないこと
- Service Workerでのオフライン再読込、別アプリのキャッシュ保持

この検査はアクセシビリティ規格への完全準拠を保証するものではありません。Android実機、TalkBack、日本語IME、ソフトキーボードとノッチを含む操作、Capacitor WebViewは別途実機確認が必要です。公開中の利用者のDBには触れていません。
