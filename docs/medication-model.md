# お薬ノートと参考推移モデル

## 使い方

1. 下部ナビゲーションの「お薬」から「薬を登録」を開き、名前・剤形、通常の有効成分1回量（mg）、T-max（時間）、消失半減期（時間）を入力します。数値の出典もメモできます。別の薬・剤形は別登録にしてください。
mg欄は`0.25`・`.5`・全角の`０．５`などの小数入力に対応し、保存時に半角の数値へ統一します。カンマや単位が含まれる入力は、誤った量に変換せずエラーを表示します。

2. カードの「服薬を記録」で入力済みのフォームを開き、今回のmg量・服薬日時・時刻の確実性を確認して保存します。登録操作だけでは服薬記録は増えません。
3. **「分析」タブの「お薬の推移をみる」**で薬と計算用体重を確認します。「お薬」カードの「推移」からも移動できます。グラフを最上部、その下に操作欄を配置し、長い計算説明・数値表は折りたたんでいます。現在以前の最新の有効な体重記録を初期値に使います。手入力した体重は計算専用で、体重記録を書き換えません。
4. 実際の服薬記録の重ね合わせ、または登録量1回のモデルを選択できます。後者は表示開始時刻に1回服用した仮想条件で、服薬の提案・予定作成ではありません。
5. 「最初に表示する薬」を選び、「重ねて表示する薬」のチェックで最大6種類を同じ座標上に表示できます。色と線種の両方で識別し、凡例・時刻スライダー・数値表でも薬ごとの値を確認できます。チェック解除でその線を外せます。選択内容は画面を開いている間だけ保持します。
6. 表示範囲を6・12・24・48・72・168時間から選び、スライダーと3時間ごとの表でも確認できます。グラフの最大値は標本点での最大値であり、厳密な連続関数の最大値とは限りません。

薬剤情報の検索・推奨値の自動設定・外部送信はありません。利用者の実際の薬や個人データを開発・テストに使用していません。

## グラフを見やすくする操作

グラフ最上部・操作欄が下側の配置は維持しています。下側の操作欄で次を選べます。

- **縦軸の表示**: 共通軸（初期値）、左右2軸、薬ごとの独立軸（段組み）。左右2軸では各薬を左・右のどちらに置くか選べます。薬別表示では時間軸をそろえた複数の図に分かれます。
- **横軸の単位**: 日時、表示開始からの分・時間・日。経過時間の基準は服薬時刻ではなく全線共通の表示開始日時です。切り替えても計算値や表示範囲は変わりません。
- **表示範囲**: 6時間から7日間まで。「現在を中心に表示」で現在時刻を中央に、「最新の服薬に合わせる」で表示対象の最新の計算可能な服薬を範囲の4分の1の位置に置きます。服薬の提案や記録の変更は行いません。
- **時刻の確認**: グラフをタップするか、従来の時刻スライダーを操作します。薬別表示でも全図のカーソルが同じ時刻に動き、数値は薬ごとに表示されます。

軸の上限は表示範囲内の標本点の最大値から余白を設け、1・2・5などの読みやすい値に切り上げます。目盛りの変更でモデル値を正規化・合算することはありません。表示設定は画面を開いている間だけ保持し、DBを変更しません。

## 表示単位と限界

名前、mg、T-max、半減期、体重だけでは絶対的な血中濃度は決まりません。

- **mg/kg**: F＝1を仮定した、モデル内薬物量を体重で割った値です。血中濃度ではありません。表示軸と説明文にもこの区別を表示します。
- **mg/L**: 濃度モデル用のF（バイオアベイラビリティ、0超〜1）と見かけの分布容積（L/kg）が、計算対象の全記録にある場合だけ表示します。分布容積を`体重 × L/kg`として計算したモデル濃度で、測定値でも、個人への妥当性が確認された予測値でもありません。

表示範囲全体に同じ体重を使います。体重は分布容積またはmg/kgの分母に反映し、半減期・クリアランスの個別補正は行いません。記録の一部にFまたは分布容積がない場合は、全体をmg/kgに統一し、すべての記録でF＝1を仮定します。異なる薬の線は同一座標に表示しますが、薬同士の値は合算しません。**線の高さから薬の強さ・効果・安全性を比較することはできません。** 全ての表示線の記録にFと分布容積がある場合だけmg/Lを使い、どれかの線で不足する場合は全線をmg/kg（全記録でF＝1を仮定）に統一します。mg/Lとmg/kgを同じ軸に混在させません。共通軸では全線が同じ倍率、左右2軸では左右ごと、薬別の段組みでは薬ごとの倍率になります。倍率が異なる場合は線の高さを直接比較せず、凡例に表示される使用軸・上限値と数値表を確認してください。計算可能な記録がない薬は理由を表示し、ゼロの線は作成しません。

モデルは経口投与の1コンパートメント・一次吸収・一次消失、吸収ラグなし、線形動態を仮定します。多コンパートメント、徐放・遅延放出、非線形動態、食事、相互作用、活性代謝物、腎肝機能、年齢、個人差を扱いません。**効果・安全性、用量、服用間隔、次の服薬時刻、運転や飲酒の可否を判断するために使えません。** 有効域・危険域や服薬推奨は表示しません。

## 数式

`D`: 今回量mg、`W`: 体重kg、`Tmax`: 時間、`H`: 消失半減期（時間）。

```text
ke = ln(2) / H
Tmax = ln(ka / ke) / (ka - ke)
q(t) = ka / (ka - ke) × (exp(-ke × t) - exp(-ka × t))
体重あたりのモデル内薬物量(t) = D / W × q(t)                 [mg/kg]
モデル濃度(t) = F × D / (W × Vd_L_per_kg) × q(t)             [mg/L]
```

`t <= 0`では寄与を0とし、各服薬の時刻からの経過時間で寄与を求め、同じ登録薬だけを加算します。吸収速度`ka >= ke`の範囲に限定して、T-maxの式を二分法で解きます。`Tmax > H / ln(2)`はこのモデルの対象外としてグラフから除外しますが、登録・服薬記録は可能です。吸収律速のflip-flop kineticsの解を通常の消失半減期と取り違えて採用しないためです。

`ka ≈ ke`は極限形`q(t) = ke × t × exp(-ke × t)`で計算し、それ以外も`expm1`で差の桁落ちを抑えています。グラフは337個の等間隔点に、表示範囲内の服薬時刻と各単回T-maxを追加して描きます。対象5000回を超えると明示的なエラーを表示し、記録は削除しません。

服薬日時不明、未来日時、無効な日時、mgやモデル条件の不足、不適合なT-max／半減期の記録を除外し、件数を表示します。「推定」の時刻はその時刻で計算し、その件数も表示します。古い自由入力を名前から自動照合せず、編集で登録薬を選択した場合だけ連携します。古い版で文字列の服用量だけを変更して数値のmgと不一致になった記録や、トップレベルの記録日時と服薬日時が食い違う記録も計算対象から外します。

## 保存・互換性

既存の`life-log` DB version 1、`records`ストアとJSONバックアップ version 1は維持します。DBのアップグレード、既存レコードの一括変換・削除は行いません。

登録薬は別DB `life-log-medications` version 1の`medications`ストアに保存します。登録薬は「お薬」画面から、`app: life-log-medications, version: 1`の専用JSONファイルでバックアップ・復元できます。**移行時は生活記録と登録薬の両方のJSONを保存してください。** 復元は同じIDだけを上書きする統合方式で、全件を検証後に単一トランザクションで書き込みます。登録薬の復元は生活記録を変更しません。

連携する服薬は従来どおり`type: med`、`data.name`、`data.dose`、`data.time`などを維持し、次の平坦なフィールドを追加します（文字列／数値で、既存のJSON v1復元の検証を通せる形式）。

```text
medicationId, doseMg, tmaxHours, halfLifeHours,
bioavailability, vdLKg, pkSource
```

これらは記録時のスナップショットです。登録薬の編集・削除・復元で過去の服薬条件を書き換えません。記録のメモだけを編集した際も、元のスナップショットを初期選択して維持します。別の登録薬を選んだ場合だけ現在の登録値を取り込みます。明示的に自由入力に戻した場合は連携フィールドを外します。

登録薬を削除しても服薬記録は残り、保存された条件から履歴用の薬選択肢とグラフを復元できます。旧版は新フィールドを理解しないため、グラフや登録薬の復元はこの機能を含む版で行ってください。2つのDBにまたがる復元を行わず、各バックアップのトランザクションの独立性を保ちます。

Service Workerのキャッシュをv6に更新し、描画用の`chart.js`もオフライン対象にしました。旧タブが開いている間は旧シェルを維持します。

## 検証と未確認範囲

- 共通軸・左右2軸・薬別軸の正しい倍率と左右割当、横軸単位変更による値の不変、6種類の表示期間、タップと全図のカーソル同期、最新服薬・現在時刻への表示範囲移動
- 複数薬の共通座標・共通単位・独立した線の値、表示切替、6線の上限、データがない薬の通知、分析タブへの導線
- 解析解（`ka = 2ke`）との濃度・ピーク値比較、数値積分によるAUCの照合
- 用量・体重・F・分布容積の倍率、反復投与の線形加算、同一速度の極限、極端な正値、無効値、不適合条件、文字列とmgの不一致の検査
- Chromiumで登録・編集・削除、スナップショット保持、旧記録の連携・解除、未来／不明時刻の除外、体重の出典、保存失敗時の入力保持
- 登録薬JSON往復・不正ファイルの全件拒否・書込途中の中断時の全件ロールバック、服薬スナップショットを含む生活記録JSON v1の往復、既存DBのversion 1維持と記録保持
- 両テーマのaxe（WCAG 2 A/AA・2.1 AA対象）、ダイアログ、数値表、スライダーのキーボード操作、320/390/768px表示とナビゲーションの操作サイズ
- 既存の全生活記録機能、バックアップ、登録薬DBが使えない場合の自由入力継続、オフラインシェルとお薬グラフのローカル計算の回帰テスト

実在薬の臨床データへの適合確認、医療機器としての検証、Android実機・TalkBack・Capacitor WebViewは実施していません。

## 計算方式の参考資料

- Holford N. [Absorption and Half-Life](https://doi.org/10.12793/tcp.2016.24.4.157), Translational and Clinical Pharmacology (2016): 一次吸収と消失、半減期、濃度式、蓄積の解説。
- FDA/ICH [S3A: Note for Guidance on Toxicokinetics](https://www.fda.gov/media/71990/download): T-max、半減期、バイオアベイラビリティ、分布容積などの薬物動態パラメータの定義。

これらを参考にした一般的な数理モデルの実装であり、個々の薬・利用者に対してこのモデルが妥当であることを示すものではありません。
